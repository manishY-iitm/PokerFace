Poker Face: Offline Privacy Firewall for Multilingual Health Records

Track 3, Secret Wards | Team Poker Face: Suyash Krishan Garg, Manish Yadav, Shubh Singh Rajput, Khushi Sarawagi | github.com/Neo-Venom/PokerFace

1. Problem

Hospital records mix English, Hindi and Hinglish, with personal data in text, fields, filenames and metadata. Our goal is to remove identities, keep clinical information, and link records without merging different patients. System RAKSHA runs 100% offline, CPU-only, without LLMs, under raksha.toml (python main.py --input {input} --output {output}).

2. Architecture

Flow: Input -> format/encoding handling -> PII detection -> patient linking -> privacy transformation -> audit -> sanitized/, report.json, records.jsonl (unprocessable files quarantined in report.json).

3. Ingestion

Formats & encodings: Handles .csv, .tsv, .json, .jsonl/.ndjson, FHIR R4 JSON Bundles, .xml, .txt/.md/.log, and JSON mislabelled .csv. Strictly decodes UTF-8, UTF-8-BOM, UTF-16 LE/BE, and cp1252; sparse NUL injections (<=0.5% bytes) convert to spaces instead of dropping whole exports. Ragged CSV rows merge overflow cells cleanly; CSV formula leads (= + - @ \t \r) are prefixed '. Quarantine: Unprocessable or unsafe inputs—PDF/JPEG/PNG/GIF/ZIP/SQLite magic bytes, empty or undecodable files, malformed or NaN JSON, JSON depth >500, XXE/DTD XML failures (defusedxml), unsafe filenames, and text lines >65,536 chars—are quarantined in report.json (output: null).

4. Detection

No ML model is used. profiler.py infers field roles from two signals: bilingual EN/HI/Hinglish header synonyms and observed cell value shapes. MedicalGuard protects doctors, ASHA/ward terms, doses (1-0-1), labs, ICD-10/LOINC codes, K/C/O, H/O, eponyms (e.g., Parkinson's), and a lexicon learned at runtime from clean docs and clinical fields. pii_regex.py and pii_ner.py detect ABHA, PAN, Aadhaar, multi-format phones, shape-based MRN/UHID, UPI/gov IDs, EN/Devanagari/Hinglish names, S/o/D/o/W/o/C/O <name> relatives (separating C/O <complaint>), and fail-closed non-district addresses, then sweep all harvested tokens corpus-wide. hidden.py recursively decodes %XX, HTML entities, \uXXXX, homoglyphs, zero-width/BiDi chars, hex, Base64, and bounded (8 MiB, depth 4) gzip+Base64.

5. Linking and pseudonyms

Signals & rules: Multi-key blocking pairs records via UHID/core IDs, gov IDs, phones, emails, names, relatives, DOB/birth year, village, and district. IDF-weighted Fellegi–Sunter scoring (threshold 7.5) compares Latin and ITRANS-romanized Devanagari using Jaro–Winkler and vowel/aspiration-folded consonant keys. Vetoes & abstention: Hard vetoes block merges across conflicting Aadhaar/ABHA/PAN/last-4, sex, age/DOB, same-system non-episode MRNs, twins/father-son, shared attendant phones without matching people, and multi-patient tables. Weak records require margin >=2.5 and coincidence <=0.25; ambiguous or multi-patient records stay patient: null. Linked clusters get keyed HKDF-SHA256 + HMAC-SHA256 pseudonyms (PSN-XXXXXXXX).

6. What distinguishes our design

Dual-signal schema agnosticism

Columns and JSON keys classify from both header/key labels and cell shapes, surviving renamed headers (holder, abode) and mixed-language dumps with zero hardcoded test IDs.

Cross-script identity with vetoes & egress gate

Links Devanagari/Latin/Hinglish mentions while blocking parent-child/twin false merges via hard vetoes and null abstention, then re-audits outputs, filenames and decoded payloads before exit.

7. Privacy and utility

Transformations (config/policy.yaml, kanon.py, date_shifter.py): Each patient cluster gets a keyed HMAC shift (±30–180 days, dodging DOBs) that keeps exact lengths of stay and visit gaps across all date formats. Exact DOBs become cohort ranges (or are omitted in FHIR Patient). Distinct patient clusters generalize along a truthful age-band ladder (5y -> 10y -> 20y -> 0-17/18-59/60+ -> 0-17/18-120, 85+ top-code). Patients with rare diagnoses (<4 clusters, excluding complaint durations) require stricter 2k (10) patients plus l_diversity = 2 distinct primary conditions (not ICD rollup). Districts stay; villages/houses/landmarks are scrubbed; tehsils and 3-digit PIN prefixes release only if cohort size suffices. Choice & cost: stronger generalization reduces linkage risk (A3/A4) but removes age/sub-district detail, while keeping exact stays and raw diagnoses preserves research utility at higher known-fact attack exposure (A5).

8. Security

Implemented controls: KeyRing.from_env derives HKDF subkeys (pseudonym, date-shift, file-name, vault), pops RAKSHA_SECRET from os.environ, and zeroes keys on exit. Logs suppress tracebacks (FATAL: <ExcType>), --input is untouched, and no temp files are written. encrypt_quarantine_archive defaults to false: released sanitized/, report.json, and records.jsonl are plaintext UTF-8 (no quarantine blobs stored by default); when enabled, EncryptedVault seals quarantined raw files to quarantine/<rel_input_path>.enc with AES-256-GCM (12B nonce, SHA-256 AAD). Disclosed security & audit gaps: (1) empty/missing RAKSHA_SECRET falls back to a fixed key instead of failing closed; (2) audit.py calls unbounded gzip.decompress and fhir_handler.py calls uncapped b64decode; (3) audit skips secrets <4 chars, omits URL-safe -_ Base64 in _B64_RE, only checks secrets on is_clean_doc files, and only forces quarantine on 6 critical ID types (leaving MRN/phone/PIN/names to best-effort re-scrubbing); (4) main.py re-execs -X utf8 before env scrub; (5) FHIR sanitization is structural, not a full R4 validator.

10. Models and dependencies

No ML model is used (0 LLMs, 0 neural/CRF weights). Seven offline CPU libraries in requirements.txt: regex, rapidfuzz, jellyfish, indic-transliteration, cryptography, defusedxml, pyyaml, plus static clinical/name/district/ICD-title tables in data/ (no truth keys). Optional demo server ui/ uses stdlib only.

11. Verified known limitations

  • Unfamiliar ID prefixes, encoded text and canaries can leak (e.g., Synthetic CAN06 bp-456178; Stress direct IDs).
  • Shared doctor and patient names can cause leaks when clinical spans shield an overlapping patient name.
  • Shifted CSV rows can cause leaks, lost data or wrong merges (PSN-2YP7Y1PK in synthetic debugging).
  • Hindi durations can be mistaken for ages during inline rewriting; non-Devanagari Indic scripts lack transliteration.
  • Some valid files are quarantined by strict limits (depth >500, lines >64 KiB, strict filename characters).
  • Some linked records lack the pseudonym inside the sanitized text/record (9,713 / 9,829 consistency on Synthetic).
  • Known-fact attacks remain a significant risk (Practice attack simulation A5 58.3%; rare diagnoses keep exact stays).
  • Zero leakage on unseen data is not guaranteed.
